## 一、商业模式与角色定义

### 1.1 角色关系

```
┌──────────────────────────────────────────────────────────────────┐
│                      QuantumClaw 平台                              │
│                                                                   │
│  ┌──────────┐  ┌──────────────────┐  ┌──────────────────────┐    │
│  │  平台官方 │  │ 渠道商（推广者）  │  │  Key 贡献者          │    │
│  │  (自营)   │  │  张三             │  │  李四                │    │
│  ├──────────┤  ├──────────────────┤  ├──────────────────────┤    │
│  │ 自有 Key  │  │ 拉用户 → 赚佣金  │  │ 提供 Key → 赚资源费  │    │
│  │ 运营平台  │  │ 也可贡献 Key    │  │ 也可拉用户赚佣金    │    │
│  │ 兜底服务  │  │ 也可不贡献 Key  │  │ 角色可叠加          │    │
│  └──────────┘  └──────────────────┘  └──────────────────────┘    │
└──────────────────────────────────────────────────────────────────┘
```

**关键：一个人可以同时是多个角色。** 张三既可以拉用户（推广拿佣金），也可以把自己的 Key 接入池子（贡献 Key 拿资源费）。

### 1.2 资金流模型（核心公式）

```
总营业额 = 用户按渠道商定价支付

逐笔分账:
  ├── 推广佣金 = 总营业额 × 推广佣金率(model)
  │    付给：带来用户的渠道商（可能是张三，也可能无）
  │
  ├── 平台抽佣 = 总营业额 × 平台抽佣率(model)
  │    付给：平台自己
  │
  └── 统一成本 = 该模型配置的固定统一成本 × tokens量
       付给：实际贡献 Key 的人（李四）
         └ 李四利润 = 统一成本 - 李四实际成本
```

**收支平衡验证（例：gpt-4o @ $10/M）：**

| 分账项 | 金额 | 比例 | 说明 |
|--------|------|------|------|
| 总营业额 | $10.00 | 100% | 用户付给平台（按张三定价） |
| 推广佣金 | $3.00 | 30% | 张三的推广佣金率 |
| 平台抽佣 | $1.00 | 10% | 平台抽佣率 |
| 统一成本 | $6.00 | 60% | GPT-4o 配置的统一成本 |
| **合计** | **$10.00** | **100%** | ✅ 收支平衡 |

**验证公式：推广佣金 + 平台抽佣 + 统一成本 = 总营业额 → 3 + 1 + 6 = 10 ✅**

### 1.3 三个可配置参数

| 参数 | 配置粒度 | 说明 |
|------|---------|------|
| 统一成本（unified_cost） | **按模型** | 每个模型一个固定成本值，如 gpt-4o = $6/M, deepseek-chat = $0.5/M |
| 推广佣金率（commission_rate） | **按模型** | 每个模型一个百分比，如 30% |
| 平台抽佣率（platform_fee） | **按模型** | 每个模型一个百分比，如 10% |

### 1.4 角色收入来源一览

| 角色 | 收入来源 | 计算方式 | 条件 |
|------|---------|---------|------|
| **张三（推广人）** | 推广佣金 | 总营业额 × 该模型佣金率 | 用户通过张三的推广链接注册 |
| **李四（Key 贡献者）** | 资源费 | 统一成本（全额给付） | 实际路由选了李四的 Key |
| **平台** | 抽佣 | 总营业额 × 平台抽佣率 | 每次调用 |
| **张三（同时是 Key 贡献者）** | 佣金 + 资源费 | 两笔叠加 | 既推广了用户，又贡献了 Key |

### 2.2 settlement_config（结算配置）

每个模型一条，一个特殊的 `*` 行作为默认兜底。

```sql
CREATE TABLE settlement_config (
  id                INT PRIMARY KEY AUTO_INCREMENT,
  model_name        VARCHAR(255) NOT NULL,       -- 模型名（如 gpt-4o, * 为默认）
  unified_cost      DECIMAL(10,6) NOT NULL,       -- 统一成本（单位: USD/1K tokens）
  commission_rate   DECIMAL(5,4) NOT NULL,        -- 推广佣金率（如 0.30 = 30%）
  platform_fee_rate DECIMAL(5,4) NOT NULL,        -- 平台抽佣率（如 0.10 = 10%）
  enabled           TINYINT(1) DEFAULT 1,
  created_time      BIGINT NOT NULL,
  updated_time      BIGINT NOT NULL,
  UNIQUE KEY idx_model_name (model_name)
);
```

**查询优先级（`getSettlementConfig` 逻辑）：**
```
1. model_name 精确匹配 → 2. * 默认配置
```

举例数据：

| model_name | unified_cost | commission_rate | platform_fee_rate |
|-----------|-------------|----------------|------------------|
| gpt-4o | 0.006000 | 0.30 | 0.10 |
| gpt-4o-mini | 0.001500 | 0.30 | 0.10 |
| claude-3.5-sonnet | 0.003000 | 0.30 | 0.10 |
| deepseek-chat | 0.000500 | 0.25 | 0.10 |
| deepseek-reasoner | 0.001000 | 0.25 | 0.10 |
| * | 0.001000 | 0.20 | 0.15 |

### 2.3 token_transaction（交易流水）

每笔 API 调用一条记录，记录完整的资金流向。

```sql
CREATE TABLE token_transaction (
  id                  BIGINT PRIMARY KEY AUTO_INCREMENT,

  -- 调用基本信息
  log_id              INT NOT NULL,              -- 关联 log 表
  user_id             INT NOT NULL,              -- 消费的用户
  model_name          VARCHAR(255) NOT NULL,     -- 模型名
  prompt_tokens       INT NOT NULL DEFAULT 0,
  completion_tokens   INT NOT NULL DEFAULT 0,
  total_tokens        INT GENERATED ALWAYS AS (prompt_tokens + completion_tokens) VIRTUAL,

  -- 路由信息
  channel_id          INT NOT NULL,              -- 实际被调用的 Channel
  channel_owner_id    INT NOT NULL DEFAULT 0,    -- Channel.UserId（0=平台, >0=Key 贡献者）
  promoter_id         INT NOT NULL DEFAULT 0,    -- 推广人（0=无推广）
  fallback_from       INT DEFAULT NULL,          -- 兜底来源：NULL=正常, promoter_id=兜底给推广人

  -- 金额字段（单位: USD，精确到小数点后 8 位）
  unit_price          DECIMAL(16,8) NOT NULL,    -- 用户单价（渠道商定价）
  total_amount        DECIMAL(16,8) NOT NULL,    -- 总营业额 = unit_price × total_tokens / 1000
  unified_cost        DECIMAL(16,8) NOT NULL,    -- 统一成本（与 settle_config 一致）
  commission_amount   DECIMAL(16,8) NOT NULL,    -- 推广佣金
  platform_fee        DECIMAL(16,8) NOT NULL,    -- 平台抽佣

  -- Key 贡献者核算（实际成本由 key 贡献者自己填，仅用于对账）
  key_provider_cost   DECIMAL(16,8) DEFAULT 0,   -- Key 贡献者填写实际成本
  key_provider_profit DECIMAL(16,8) GENERATED ALWAYS AS (unified_cost - key_provider_cost) VIRTUAL,

  -- 时间
  created_time        BIGINT NOT NULL,

  -- 索引
  INDEX idx_promoter (promoter_id),
  INDEX idx_channel_owner (channel_owner_id),
  INDEX idx_user (user_id),
  INDEX idx_model (model_name),
  INDEX idx_created (created_time)
);
```

## 三、路由引擎变更（核心：链式 failover）

### 3.1 当前路由流程

```
用户请求 → TokenAuth → ModelRateLimit → Distribute → RelayToChannel
                    ↑              ↑
                鉴权+取模型     确定可用 channel
                +确定 user_group  (随机选最高 priority 的 channel)
```

**当前 `Distribute()` 的问题：**
- 一次只选一个 channel
- 如果失败，直接报错，没有 fallback
- 所有 channel 混在一起，没有按 UserId 区分

### 3.2 改造后路由流程

所有用户走同一套逻辑，没有特例分支：

```
用户请求 → TokenAuth → ModelRateLimit → Distribute' → RelayToChannel
                                              │
                                     ┌────────┴────────┐
                                     │  统一查推广人    │
                                     │  affiliate_relation │
                                     │  无推广人 → promoter=0(平台) │
                                     └────────┬────────┘
                                              │
                                     ┌────────┴────────┐
                                     │  第一层：用自己的 │
                                     │  UserId=promoter  │
                                     │  ├ promoter=平台(0) → 平台 Key │
                                     │  └ promoter=张三  → 张三的 Key │
                                     └────────┬────────┘
                                              │ 成功 → 记录流水 → ✅
                                              │ 失败/不够
                                              ▼
                                     ┌──────────────────────┐
                                     │  第二层：全资源池兜底  │
                                     │  所有渠道商 Key 混用  │
                                     │  （不限制 UserId）    │
                                     └────────┬─────────────┘
                                              │ 成功 → 记录流水 + 标记兜底 → ✅
                                              │ 失败
                                              ▼
                                     ┌────────────────┐
                                     │  全部失败→报错   │
                                     └────────────────┘
```

**

### 3.3 `Distribute()` 伪代码（统一路由）

```go
func Distribute() gin.HandlerFunc {
  return func(c *gin.Context) {
    user := getCurrentUser(c)
    model := c.GetString(ctxkey.RequestModel)
    userGroup := c.GetString(ctxkey.Group)

    // ── Step 1: 查推广人（所有人都有，0=平台自己）──
    promoterId := getPromoterId(user.Id)
    c.Set(ctxkey.PromoterId, promoterId)

    // ── Step 2: 第一层——用推广人自己的 channel ──
    //    promoterId=0 → 用平台自己的 Key
    //    promoterId=张三 → 用张三的 Key
    channel, err := getSatisfiedChannelByOwner(userGroup, model, promoterId)
    if err == nil {
      c.Set(ctxkey.ChannelOwner, channel.UserId)
      c.Set(ctxkey.IsFallback, false)
      setupContext(c, channel, model)
      go postProcessRelay(c, channel, promoterId, false)
      c.Next()
      return
    }

    // ── Step 3: 第二层——全资源池兜底 ──
    //    不限 UserId，所有渠道商 Key 混用
    poolChannel, err := getSatisfiedChannelAnyOwner(userGroup, model)
    if err == nil {
      c.Set(ctxkey.ChannelOwner, poolChannel.UserId)
      c.Set(ctxkey.IsFallback, true)
      c.Set(ctxkey.FallbackFrom, promoterId)
      setupContext(c, poolChannel, model)
      go postProcessRelay(c, poolChannel, promoterId, true)
      c.Next()
      return
    }

    // ── Step 4: 全部失败 ──
    abortWithMessage(c, http.StatusServiceUnavailable,
      fmt.Sprintf("模型 %s 当前无可用渠道", model))
  }
}
```

### 3.4 缓存结构改造

```go
// 当前:
//   group2model2channels[group][model] → []*Channel
//
// 改造:
//   group2model2channels[group][model] → map[int][]*Channel
//     map[0]        = 平台渠道（UserId=0）
//     map[promoterId] = 渠道商渠道（UserId=promoterId）

func CacheGetRandomSatisfiedChannel(group string, model string, ownerId int) (*Channel, error) {
  channels := group2model2channels[group][model][ownerId]
  if len(channels) == 0 {
    return nil, errors.New("no channel found for owner")
  }
  // 按 priority 分组，随机选最高 priority 的
  return selectByPriority(channels), nil
}

func CacheGetPlatformChannel(group string, model string) (*Channel, error) {
  return CacheGetRandomSatisfiedChannel(group, model, 0)
}

func CacheGetResellerChannel(group string, model string, resellerId int) (*Channel, error) {
  return CacheGetRandomSatisfiedChannel(group, model, resellerId)
}
```

## 四、结算引擎

### 4.1 实时结算流程

```
API 调用成功 → relay 完成
  ↓
postProcessRelay(c, channel, promoterId, isFallback)
  ↓
1. 从 c 获取: user_id, model, prompt_tokens, completion_tokens
2. 查 settlement_config（按 model_name 匹配）
3. 计算金额
4. 写入 token_transaction 表
5. 更新相关余额（reseller.balance）
  ↓
完成
```

### 4.2 金额计算逻辑

```go
func calculateSettlement(c *gin.Context, config *SettlementConfig, channel *model.Channel, promoterId int, totalTokens int) *TokenTransaction {
  // 1. 用户单价：按渠道商（推广人）的定价
  unitPrice := getUnitPrice(promoterId, channel, config)

  // 2. 基础计算
  totalAmount := unitPrice * float64(totalTokens) / 1000.0

  // 3. 分账
  unifiedCost     := config.UnifiedCost * float64(totalTokens) / 1000.0
  commissionAmount := totalAmount * config.CommissionRate
  platformFee     := totalAmount * config.PlatformFeeRate

  return &TokenTransaction{
    UserId:           c.GetInt(ctxkey.Id),
    ModelName:        c.GetString(ctxkey.RequestModel),
    PromptTokens:     c.GetInt(ctxkey.PromptTokens),
    CompletionTokens: c.GetInt(ctxkey.CompletionTokens),
    ChannelId:        channel.Id,
    ChannelOwnerId:   channel.UserId,
    PromoterId:       promoterId,
    UnitPrice:        unitPrice,
    TotalAmount:      totalAmount,
    UnifiedCost:      unifiedCost,
    CommissionAmount: commissionAmount,
    PlatformFee:      platformFee,
    CreatedTime:      time.Now().Unix(),
  }
}
```

## 五、全链路影响分析

### 5.1 数据流全景

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   用户注册       │     │  渠道商入驻      │     │  Key 贡献者接入  │
│                 │     │                 │     │                  │
│  ↓ 推广码绑定    │     │  ↓ 创建 reseller │     │  ↓ 创建 channel   │
│  affiliate       │     │  ↓ 生成推广链接  │     │  ↓ 填入 cost_price│
│  _relation 写入  │     │  ↓ 配置 Key     │     │  ↓ 关联模型清单   │
│                 │     │                 │     │                  │
└────────┬────────┘     └────────┬────────┘     └────────┬────────┘
         │                      │                       │
         ▼                      ▼                       ▼
┌───────────────────────────────────────────────────────────────┐
│                      路由执行时                                  │
│                                                                 │
│  1. Distribute 查 affiliate_relation → 得 promoter_id          │
│  2. 先查 channel WHERE UserId=promoter_id → 有就用               │
│  3. 没有/全失败 → 查 channel WHERE UserId=0 → 平台兜底           │
│  4. 写入 token_transaction                                      │
└───────────────────────────────────────────────────────────────┘
```

### 5.2 影响文件清单（全量）

#### Phase 1：路由 failover（必须）

| 文件 | 操作类型 | 影响 | 风险 |
|------|---------|------|------|
| `model/ability.go` | 修改 | `GetRandomSatisfiedChannel` 加 ownerId 参数 | 低：新增参数不影响现有调用 |

## 七、关键边界条件

| 场景 | 处理方式 |
|------|---------|
| 场景 | 处理方式 |
|------|---------|
| 推广人自己的 channel 不够用/全挂 | 进入第二层——全资源池兜底，所有 Key 混用 |
| 全资源池也无可用 Key | 报错 503，记录告警 |
| 统一成本 > 总营业额 | 平台亏损，需告警 + 配置校验限制 |
| 佣金+抽佣 > 总营业额 | 配置校验拒绝保存 |
| 推广关系过期 | 自动解除绑定，promoter_id = 0（平台自己）|
| 同一个用户在多个 Key 贡献者之间路由 | 按 availability 随机选 |
| 推广关系过期 | 自动解除绑定，promoter_id = 0 |
| 同一个用户在多个 Key 贡献者之间路由 | 按可用性随机选，不是按"最大利润"选 |
| 结算配置不存在（无精确匹配 + 无 *) | 使用硬编码默认值（commission=20%, fee=10%, cost=0.001） |
| 批量并发写入 token_transaction | 使用异步队列 + 批量 insert，不阻塞主请求 |

## 八、已确认决议

| 议题 | 决议 |
|------|------|
| 统一成本 | 每个模型独立配置一个成本值 |
| 推广佣金率 | 每个模型独立配置 |
| 平台抽佣率 | 每个模型独立配置 |
| 结算周期 | 平台配置（设计预留灵活性） |
| Key 贡献者透明度 | **100% 全透明** |
| 推广关系有效期 | 平台全局配置，0=永久 |
| 语言体系 | 必须使用 T_Languages 驱动，禁止硬编码 |
| API 返回格式 | 统一 `{success, data, message}` |
