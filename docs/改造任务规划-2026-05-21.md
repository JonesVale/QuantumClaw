# QuantumClaw 平台化改造 — 完整任务规划

**定稿时间**: 2026-05-21 21:43  
**总工期预估**: ~12 个工作日（5 刀）

---

## 收费模型（最终定稿）

```
入驻免费           → 零门槛
交易抽成 1%        → 每笔 API 调用即时扣除
入驻费 5%          → 按总营业额，月结算；提现时先扣再提；月营业额 < ¥100 跳过
总平台抽成 ≈ 6%    → 供应商净得 ~94%
```

## 第零刀：前置清理（预估 1 天）

**目标**：清理历史包袱，为新体系铺路

### 0.1 修复 UnlimitedQuota 默认值

| 改动 | 文件 | 内容 |
|------|-----|------|
| 注册默认 Token | model/user.go `Insert()` | `UnlimitedQuota: true` → `false` |
| 注册默认 RemainQuota | 同上 | `RemainQuota: -1` → `0` |
| 注册默认 ExpiredTime | 同上 | `ExpiredTime: -1` → 设一个合理有效期 |

**原因**：不修这个，注册即无限额度，余额体系形同虚设。

### 0.2 存量用户额度迁移

| 改动 | 文件 | 内容 |
|------|-----|------|
| 数据迁移脚本 | scripts/ | 扫描所有存量用户，Quota > 0 的按固定汇率转现金余额 |
| 汇率确定 | config | 存量转现金汇率（如 1 额度 = ¥0.00001） |
| 迁移记录 | — | 记录迁移日志，可回滚 |

**原因**：系统升级后老的免费额度不能直接作废，也不能和新现金体系共存。

### 0.3 存量 Token 处理

| 改动 | 文件 | 内容 |
|------|-----|------|
| 所有存量 Token | 数据迁移 | UnlimitedQuota 统一改为 false，剩余额度按汇率转余额 |
| 过期 Token 清理 | scripts/ | 标记过期不用的 Token |

### 第零刀验收标准
```
✅ 新注册用户默认有限额度，不能无限用
✅ 存量用户额度已按汇率转为现金余额
✅ 存量 Token 不再有无限制的漏洞
```

| 改动 | 文件 | 内容 |
|------|-----|------|

## 第四刀：入驻费自动结算（预估 1-2 天）

**目标**：5% 入驻费按月自动扎帐，营业额 < ¥100 跳过

### 4.1 入驻费结算表

| 改动 | 文件/表 | 内容 |
|------|---------|------|
| 新建 PlatformFeeRecord 模型 | model/platform_fee.go | id, user_id, period(YYYY-MM), total_revenue, fee_rate, fee_amount, deducted_at, status(pending/deducted/skipped) |

### 4.2 入驻费自动结算

| 改动 | 文件 | 内容 |
|------|-----|------|
| 定时任务（次月 1 号） | service/platform_fee.go | 遍历所有供应商，统计上月营业额 |
| 营业额 < ¥100 → 跳过 | service/platform_fee.go | 状态标记 skipped |
| 营业额 ≥ ¥100 → 算入驻费 | service/platform_fee.go | 总营业额 × 5%，记录 pending |
| 不提现只扎帐 | service/platform_fee.go | 只记记录，不动余额，等提现时再扣 |
| 提现时扣入驻费 | controller/withdrawal.go | 把 pending 状态入驻费从可提现金额中扣走 |

### 第四刀验收标准
```
✅ 次月 1 号自动统计所有供应商上月营业额
✅ 营业额 < ¥100 → 跳过，不处理
✅ 营业额 ≥ ¥100 → 记录入驻费应扣金额（pending）
✅ 提现时入驻费被实际扣掉
```

## 依赖关系

```
第零刀 → 第一刀 → 第二刀 → 第三刀 → 第四刀 → 第五刀
  ↑         ↑         ↑         ↑         ↑         ↑
存量清理  余额充值  供应商  提现流程  入驻费  管理后台
          渠道权限  收益看板  入驻费扣  自动结算  审批+看板
```

- 第零刀必须先做，否则漏洞未堵
- 第一刀跑通前，后面不能开始
- 第三刀依赖第二刀的收益流水
- 第四刀依赖第三刀的入驻费扣款逻辑
- 第五刀依赖前面所有数据

## 风险点（保留）

| 风险 | 影响 | 缓解 |
|------|------|------|
| 抽象额度体系改现金 | 历史用户额度数据怎么处理 | 存量额度按固定汇率转现金（第零刀） |
| UnlimitedQuota 默认值 | 注册即无限额度 | 第零刀已修复 |
| Stripe 接入 | 平台需要先配 Stripe | 初期先支持管理员手动代充 |
| 供应商审核 | 人工审核耗时 | 初期自动通过，后加审核 |
| 上游成本波动 | 供应商利润被压缩 | 平台抽佣固定，不随成本波动 |
