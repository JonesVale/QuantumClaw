# QuantumClaw 渠道路由与商业逻辑完整设计方案

## 一、当前架构总览

```
用户请求 → middleware.Distribute() → controller.Relay() → relay controller → adaptor.DoRequest()
              │
              ├─ Step 1: 有 specific_channel_id？→ 直接路由
              ├─ Step 2: 查 promoter 渠道
              ├─ Step 3: 全资源池兜底（随机）
              └─ 失败 → Relay() 中 retry 随机换渠道
```

**问题：**
- 无价格考量（随机选渠道）
- 无国内/国外隔离
- 无用户首选供应商
- 无价格过高提示

## 二、三级路由原则实现方案

### 原则 1：用户指定渠道商优先

**用户设置**：User 模型新增 `preferred_provider_id` 字段
- 用户在 Profile 页设置「首选供应商」
- 路由时：检查首选供应商是否有该模型的渠道 → 有则优先使用

**路由逻辑变更**（`middleware/distributor.go`）：
```
1. specific_channel_id → 直接路由（不变）
2. preferred_provider_id > 0 → 查该供应商是否有该模型渠道
   ├─ 有 → 使用
   └─ 无 → 继续下一步
3. promoter 渠道 → 不变
4. 全资源池兜底 → 改为价格排序最低价优先
```

### 原则 2：同品牌同模型 → 最低价优先

**Channel 定价模型现状**：
- `SellPriceRate`（售价倍率）— 渠道商设置的加价倍率
- `ChannelMarkup`（加价倍率）— 已存在但含义重叠
- `CostPerUnit`（每单位成本）— 上游成本

**实现**：修改 `GetRandomSatisfiedChannel` 系列函数
- 不再 random
- 按 `(SellPriceRate + ChannelMarkup)` 排序，取最低
- 需要缓存或 DB 查询时加 `ORDER BY sell_price_rate ASC`

**数据结构**：新增 `ReferencePrice` 模型记录平台基准价
```go
type ReferencePrice struct {
    ModelName string  `json:"model_name"`
    BasePrice float64 `json:"base_price"` // 平台基准价（美分/请求）
}
```

当渠道 `SellPriceRate × CostPerUnit × 100 > BasePrice × 1.2` 时标记为「高价渠道」：
- 前端 Playground/API 响应中加 `price_warning` 字段
- 非用户推广关系的高价渠道不自动路由

### 原则 3：国内资源不自动切到国外

**实现方案**：Channel 模型新增 `region` 字段
```go
Region string `json:"region" gorm:"type:varchar(20);default:''"` // "china" / "overseas"
```

**自动判定规则**（`relay/channeltype/define.go`）：
```
国内渠道: Baidu, Zhipu (GLM), Ali (Qwen), Xunfei (Spark), 360 AI,
          Tencent (Hunyuan), Baichuan, DeepSeek, MiniMax, Moonshot (Kimi),
          Doubao (VolcEngine), StepFun, LingYi (01.AI), Jimeng, Moka AI
国外渠道: OpenAI, Anthropic, Google Gemini, Mistral, AWS, Azure,
          Cohere, Groq, DeepL, Together AI, Cloudflare, Replicate, xAI
量子:    IonQ, IBMQ(国外), Rigetti(国外), 阿里量子(国内)
```

**回退约束**：当前选中渠道为国内时，fallback 只在中国渠道内搜索
- `GetRandomSatisfiedChannel` 增加 `region` 过滤参数

## 三、资金模型修正

### 修正返佣（CommissionBalance）可消费

```
消费优先级链（修正后）：
  1. 订阅额度
  2. CashBalance（现金余额）
  3. CommissionBalance（佣金余额）← 新增
  4. Quota（旧配额）
```

- CommissionBalance 同时支持消费和提现
- 消费时：从 CommissionBalance 扣（与 CashBalance 同级但优先级更低）
- 提现时：从 CommissionBalance 扣
- 记录消费来源（cash / commission / quota）到日志

### API Key 软删除

```go
// Channel 模型增加
DeletedAt gorm.DeletedAt `json:"deleted_at"` // GORM soft delete
```

- 供应商删除 → GORM `Delete()` 转为设置 `deleted_at`
- 供应商仍可见自己的 key（加 `Unscoped()`）
- 管理员后台可见所有（包括软删除）
- 路由时自动过滤 `deleted_at IS NOT NULL`

### 收入结算对账

```
每笔消费:
  ConsumerDeduct (用户扣款)
    → 平台收入: priceCents × platformFeeRate
    → 供应商收入: priceCents × (1 - platformFeeRate)

月结:
  汇总 ProviderEarning (按月 period)
  比对: ∑ConsumerDeduct - ∑CommissionAmount = 平台实收
  入驻费: 月营业额 ≥ ¥100 → 扣入驻费
```
