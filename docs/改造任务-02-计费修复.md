## P0：修复计费扣款可靠性（1.5 天）

### P0-1：PostConsumeDeduct 同步化

**现状**：
```go
go postConsumeDeduct(...)  // goroutine，失败无声
```

**方案**：去掉 `go`，改为同步执行。扣款失败 → API 响应中也返回错误。

**影响分析**：

| 文件 | 改动 | 
|------|------|
| `relay/controller/text.go:89` | `go postConsumeDeduct` → `postConsumeDeduct` |
| `relay/controller/helper.go` | `postConsumeDeduct` 返回值改为 `error` |
| `service/cash_billing.go` | `PostConsumeDeduct` 返回值改为 `error` |

**风险**：API 响应时间会增加几十毫秒（一次 DB 写入），但可以保证扣款一定执行。

### P0-2：错误日志不吞掉

**现状**：
```go
_ = model.CreateBalanceLog(...)
_ = model.CreateProviderEarning(...)
```

**方案**：改为日志记录：
```go
if err := model.CreateBalanceLog(...); err != nil {
    logger.Error(ctx, "create balance log: " + err.Error())
}
```

**改动文件**：`service/cash_billing.go`

## P1：权限与事务修复（1 天）

### P1-1：SetChannelPricing 移到 AdminAuth

**现状**：`POST /channel/pricing` 在 UserAuth 路由组，任何登录用户可调用

**方案**：移到 AdminAuth 路由组

**改动文件**：`router/api.go`

### P1-2：入驻费扣除 + 提现统一事务

**现状**：先扣入驻费（独立事务），再创建提现记录（独立事务）。中间可能崩溃。

**方案**：两个操作放到同一个 GORM Transaction 中。

**改动文件**：`controller/withdrawal.go` → 用 `model.DB.Transaction(func(tx *gorm.DB) error { ... })` 包裹入驻费扣除 + 提现记录创建
